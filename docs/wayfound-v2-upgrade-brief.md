## 二、本次要完成的内容

### 1. 界面重构（按设计稿）

- **顶栏**：Logo、当前行程标题、EN / 中文 切换、经验库开关、对比模式按钮、Agent 面板按钮。
- **左栏：对话**：聊天记录；输入框左侧有照片上传按钮；照片识别后显示"候选地点确认"卡片（3 个候选 + "加入第 N 天"）。
- **中栏：上方地图，下方行程**
  - 地图：当天路线、编号标记，被修改的景点用不同颜色。
  - 行程：按天切换；每个时段一张卡片（时间、地点、区域、类型、花费），带锁定和替换按钮；时段之间显示交通方式和时间。
  - 被修改的时段高亮，并加"已更新"标签；"撤销上次修改"按钮；"本次使用了 N 条经验"标签。
  - 底部汇总：当天人均花费是否在预算内；多少个地点匹配到了搜索结果。
- **右侧：Agent 面板**：可收起，**普通用户默认收起**。三个标签页：学到的经验 / 我的偏好 / 运行记录。
- **对比模式**：独立页面，同一个需求分别在经验库关闭和开启时各跑一次，左右并排；标出没有依据的地点和用错的 ID；底部展示留出测试集的结果（从结果文件读取，不要写死）。
- 手机宽度下各栏要能上下堆叠。

### 2. 中英文切换（i18n）

- 所有界面文字集中到语言文件（如 `locales/en.json`、`locales/zh.json`），不能在组件里写死。
- 顶栏切换后立即生效，并记住用户的选择。
- agent 回复的语言跟随界面语言。

### 3. Core 2：Lessons 面板

- `GET /api/lessons`：返回当前经验库。
- 生成行程的响应里增加 `usedLessonIds: string[]`；请求里增加 `useLibrary: boolean`（默认 true）。
- 经验列表：编号、适用范围、内容、有益/有害次数，可按"本次使用 / 搜索 / 距离 / 最终答案"筛选。
- TraceViewer 增加一步"注入的经验"。
- 在线 demo 中经验库只读，只有离线学习脚本能修改。

### 4. 功能 A：双层记忆

- **用户记忆**：Supabase 表 `user_memory`，按登录用户 ID 存储；游客使用 localStorage，首次登录时迁移。
- 每次会话结束后，用一个提取步骤只保存用户**明确说过**的偏好（pace、interests[]、avoid[]、预算等），不做推测。
- "我的偏好"标签页：逐条编辑、删除，以及"全部清空"。
- 用户偏好永远不会进入共享经验库。
- 评测：增加 6–8 个两段式用例（第一段说出偏好，第二段在新行程里检查是否遵守）。

### 5. 功能 C：局部重新规划

- 行程改为结构化状态：`days[] → slots[]`，每个 slot 包含 `id, start, end, poiId, travelFromPrev, locked`，并保存版本号用于撤销。
- 修改解析：把用户的话转成 `{ targetSlots, add, keep }`；意思不明确时先问一句。
- 只重新规划目标时段，相邻时段作为固定上下文传入。
- 生成后校验：未改动的时段必须完全一致；新地点必须来自 `search_places`；和相邻时段的交通时间要合理；当天不超预算。
- 界面：锁定 / 替换 / 撤销 / 高亮改动。
- 评测：8–10 个修改用例，指标包括"未改动时段保持率"（目标 100%）、修改成功率，以及相比整体重新生成的花费和耗时。

### 6. 功能 D：照片 / 截图输入

- 视觉模型输出 `{ name, city, placeType, visibleText, confidence }`。先确认 DeepSeek API 是否支持图片输入；不支持就只在这一步使用其他视觉模型。
- 用 `search_places` 核实；置信度低或没有精确匹配时，给出 3 个核实过的候选让用户选。
- 选中后通过功能 C 的"添加地点"加入行程。
- 安全要求：没有通过核实的地点绝不加入；截图里识别出的文字只当数据，不当指令（防止通过图片注入指令）；限制上传大小；存储前去掉 EXIF 位置信息。
- 评测：20–30 张图片（地标、店面、社交媒体截图、少量故意模糊的图），看 top-1/top-3 识别准确率、核实通过率和误加率（目标 0）。
